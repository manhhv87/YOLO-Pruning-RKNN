Note.txt — Hướng dẫn dùng script push_all_with_lfs_batches.sh (Git Bash trên Windows)
===================================================================================

Mục tiêu
--------
Script giúp:
- Add/commit nhiều file (>= 1000 file) theo lô (batch) để tránh treo máy / commit quá nặng
- Tùy chọn xử lý file lớn > ngưỡng (ví dụ >100MB):
  - Bật Git LFS để push được file lớn
  - Hoặc tắt LFS và bỏ qua file lớn (chỉ push file nhỏ)

Yêu cầu
-------
- Windows + Git Bash (Git for Windows)
- Repo đã có remote "origin" trỏ tới GitHub
- Nếu muốn push file >100MB: cần cài Git LFS

Kiểm tra nhanh trước khi chạy
-----------------------------
1) Vào đúng thư mục repo:
   cd "D:/path/to/your/repo"

2) Kiểm tra trạng thái:
   git status

3) Kiểm tra remote:
   git remote -v

Nếu chưa có remote:
   git remote add origin https://github.com/<user>/<repo>.git

Cách chạy script
----------------
Cú pháp:
  ./push_all_with_lfs_batches.sh <BATCH> <THRESHOLD_MB> <USE_LFS>

Trong đó:
- BATCH: số "paths" / lần commit (ví dụ 300/500/1000)
- THRESHOLD_MB: ngưỡng file lớn (ví dụ 100 nghĩa là >100MB)
- USE_LFS:
    1 = dùng Git LFS cho file > THRESHOLD_MB (push được file lớn)
    0 = không dùng LFS, bỏ qua file lớn > THRESHOLD_MB (chỉ push file nhỏ)

Ví dụ phổ biến:
1) Commit mỗi 500, file >100MB dùng LFS:
   ./push_all_with_lfs_batches.sh 500 100 1

2) Commit mỗi 500, bỏ qua file >100MB (không LFS):
   ./push_all_with_lfs_batches.sh 500 100 0

Gợi ý chọn tham số
------------------
- Nhiều file nhỏ (1000–10000): BATCH=500 hoặc 1000 thường ổn
- Nếu máy yếu / repo nặng: dùng BATCH=300
- Nếu bạn có model weights/zip lớn: THRESHOLD_MB=100 và USE_LFS=1

Quy trình chuẩn để tránh lỗi push (khuyến nghị)
-----------------------------------------------
1) Đồng bộ remote trước:
   git pull --rebase origin main

2) Copy thêm file vào repo (nếu có)

3) Chạy script:
   ./push_all_with_lfs_batches.sh 500 100 1

Lưu ý quan trọng về file lớn >100MB
-----------------------------------
- GitHub chặn push file >100MB bằng git thường.
- Nếu USE_LFS=0: script sẽ SKIP các file >THRESHOLD_MB để tránh push fail.
- Nếu USE_LFS=1: script sẽ tự "git lfs track" theo đường dẫn file và commit .gitattributes.

Các lỗi thường gặp & cách xử lý nhanh
-------------------------------------
1) Non-fast-forward (push bị từ chối vì remote mới hơn):
   Lỗi dạng: rejected (non-fast-forward)
   Cách sửa:
     git pull --rebase origin main
     git push

2) Conflict / unmerged files (không commit được):
   Lỗi dạng: "Committing is not possible because you have unmerged files."
   Cách sửa:
     git status
     - Sửa conflict trong file (các đoạn <<<<<<< ======= >>>>>>>)
     - git add <file...>
     - nếu đang rebase: git rebase --continue
       nếu đang merge:  git commit
   Nếu muốn hủy:
     git rebase --abort   (khi rebase)
     git merge --abort    (khi merge)

3) Không có quyền push (permission):
   Lỗi dạng: "can not upload new objects ..." hoặc repo fork/public không cho push
   Cách sửa:
   - Đổi origin sang repo bạn sở hữu:
     git remote set-url origin https://github.com/<YOUR_USERNAME>/<YOUR_REPO>.git
     git push -u origin main
   - Hoặc xin quyền write / tạo PR từ fork của bạn.

4) Cảnh báo CRLF/LF (Windows):
   Cảnh báo dạng: "LF will be replaced by CRLF"
   Thường không ảnh hưởng. Nếu muốn hạn chế:
     git config core.autocrlf true
   Hoặc dùng .gitattributes phù hợp.

5) Git LFS chưa cài (khi USE_LFS=1):
   Cài Git LFS xong mở Git Bash mới, rồi:
     git lfs install

Mẹo kiểm tra sau khi chạy
-------------------------
- Xem còn thay đổi chưa:
  git status

- Xem commit gần nhất:
  git log --oneline -5

- Xem file đang nằm trong LFS:
  git lfs ls-files

Ghi chú
-------
- Script commit theo "paths" (đường dẫn thay đổi), không phải đúng số file tuyệt đối 100%.
- Nếu bạn đổi tên/di chuyển file nhiều, số "paths" có thể lớn hơn số file.
- Khi USE_LFS=0, các file lớn bị bỏ qua vẫn còn ở working tree (chưa được commit).

Kết thúc
--------
Nếu gặp lỗi, copy/paste 3 output sau để chẩn đoán nhanh:
  git status
  git remote -v
  git pull --rebase origin main
